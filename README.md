# WristCodex · 腕上遥控

> **v0.5.1 私有试用版**。正式签名包已覆盖安装，通过无 USB 转发的 Tailscale 确认往返及新建对话发送、清空输入、显示完成回复。[版本下载与发布状态](https://github.com/maofaw/WristCodex/releases/tag/v0.5.1)。20 次交替、长文、提醒、断连及性能结果的范围见 [v0.5.1 验证记录](docs/validation-v0.5.1.md)，旧版证据见 [v0.5 验证记录](docs/validation-v0.5.md)。

将 Android 手表变成电脑 Codex 的任务遥控器。支持文字任务提交、状态及结果查询、停止任务，以及电脑状态、锁屏、睡眠、网络唤醒和自定义 HTTP 按钮。

## 验证设备

OPPO Watch 4 Pro（OWW221），ColorOS Watch V7.1 / Android 11，32 位 ARM。手表端使用 Android 原生界面，不依赖 GMS，不需要 root 或修改 DPI。Tailscale VPN 已在该设备登录和连接；用户反馈不同网络下遥控接口可返回，具体网络质量和后台保活仍需持续测试。

## 工作方式

手表 → 受口令保护的电脑 HTTP 服务 → 本机 Codex 桌面原生接口 → 原对话中的状态及结果。

模型在电脑侧使用现有 Codex 登录，需要互联网；本项目不提供离线模型。共享模式沿用原会话编号、项目、模型、思考强度及权限，电脑关闭时不另起执行器接管。历史只读通道和短期空记录管理进程不执行模型任务。`DESKTOP_SHARED=0` 保留旧版独立助手，默认不启用共享。

## 安装

1. 下载本仓库 Releases 的 APK，导入手表安装。
2. Windows 安装 Python 3.10+ 和 Codex 桌面客户端并登录；共享模式需要客户端保持运行。
3. 复制 `server/.env.example` 为 `server/.env`，生成并填写至少 16 字符的随机 TOKEN。可用 `py -3 -c "import secrets; print(secrets.token_hex(24))"`。
4. 共享模式在 `.env` 设置 `DESKTOP_SHARED=1`；环境变量 `WATCHREMOTE_DESKTOP_SHARED` 可覆盖。默认只监听本机。要让手表访问，将 BIND 改为电脑局域网或 Tailscale IP（也可在可信环境使用 0.0.0.0），并按需配置仅允许目标网络访问 TCP 8877 的防火墙规则。
5. 运行 `server/Start-PC.cmd`。在手表连接设置填写 `http://电脑地址:8877` 和相同 TOKEN。网卡 MAC 仅网络唤醒需要。
6. 打开应用进入助手对话页，识别文字后检查再发送；电脑确认接收才清空匹配的草稿。v0.5.0 长按标题进入“更多操作”；v0.5.1 增加可见的“更多”按钮，入口如下。

## 0.5.1 界面与连接

聊天页从上到下为标题/“更多”、固定状态/待处理、原生消息列表、文字输入框，以及宽麦克风和唯一“发送”。点标题切换对话，列表顶部可新建；长按标题仍可打开更多。保留黑底终端绿、系统字体、原生复用列表和至少 48dp 的交互控件，没有装饰动画。

| 入口 | 操作 |
|---|---|
| 更多 | 刷新连接与记录、返回执行中的对话、停止当前任务、电脑控制、设置与提醒 |
| 更多 → 设置与提醒 | 电脑确认提醒开关、自动弹出确认授权、暂停全部主动提醒、连接设置、自定义接口 |
| 更多 → 电脑控制 | 查询状态、锁定、睡眠、网络唤醒及已配置的自定义按钮 |
| 状态行 → 待处理 | 查看本机对话的确认项；关闭提醒仍可手动处理 |

“暂停全部主动提醒”停止当前监听，下次打开助手时恢复；“电脑确认提醒”开关是独立保存的偏好。停止当前任务需要再次确认，已经完成的操作不会撤销。

- 提交、历史读取和语音识别分开处理。发送先显示提交反馈，原请求确认接收后只清空对应文字；提交后继续输入的新草稿保留。
- 当前公开正文以有界预览显示。服务中的后续正文最多每秒发布一次，手表将同一条中间预览合并为最多每两秒绘制一次；首段、新消息和完成不延后。私有 reasoning 不进入预览；消息按会话、回合、条目定位，列表最多保留 30 条展示记录。浏览旧历史时延后最新页替换，避免打断阅读；预览不代替最终历史。
- 共享发送遵守服务的 `can_send`。`starting`、执行中、等待确认、所有者丢失或状态无效时不发送下一条任务。原生回合和运行状态到达顺序不一致时显示同步中；接收确认先到时，也不会用上一轮完成状态重新开放发送。
- 监听只保留一条长轮询；失败按 1/2/4/8/15 秒退避，手动刷新或网络恢复可打断等待并重新读取状态。恢复连接不发送任务；送达未知的原请求不会自动重放。
- 当前本机接口仍不能安全绑定执行中补充，因此 `can_steer=false`。自动重试模型连接时只显示“模型连接重试中”，不因该状态生成待处理提醒；原始错误内容不显示在手表上。
- 已修复冷启动被回复预览挡住真实历史的问题；长消息可按需打开全文分页。应用自有弹窗按钮也保持至少 48dp。
- 问题选项及自由回答按原文提交，保留首尾空白，不改变原始选项；空回答不能提交。包含空白选项、敏感输入或不支持类型的请求留在电脑处理。

当前源码通过 88 项服务及主机 JVM 检查，以及 Android 构建/lint；真实语音、四页全文、二次确认停止、双方先处理后旧请求失效、提醒开关和断连恢复已有设备记录。正式包升级保留原对话标题、服务配置及状态，系统输入法和既有密度未变；无 USB 转发时的远程问题卡片自动打开、手表回答和旧请求失效已验证。正式包新建发送已接收、清空输入，并显示正文及完成状态。短期性能指标有升有降，不承诺固定模型响应时限、零卡顿或长期后台稳定；具体范围见 [v0.5.1 验证记录](docs/validation-v0.5.1.md)。

回复等待仍有明显限制：正式包新建短问的一次实测，电脑约 119 秒才得到首段正文，约 129 秒完成。预览更新和共享报错已修复，不代表所有任务的回答都已变快；不能把此前约 3.4 秒的短答样本作为固定速度保证。

## 0.5 系列电脑共享会话

- 同一段对话在电脑和手表之间继续，原编号只出现一次。会话目录每页 20 项；近期历史按需加载，手表最多缓存 30 条展示记录，长文分页。
- 客户端实际能力决定能否发送、停止、回答；当前原生补充接口缺少回合校验，因此执行中补充明确禁用并保留草稿，本轮结束后可继续同一对话。
- 进入“更多操作”（v0.5.1 使用可见的“更多”按钮）可独立关闭“电脑确认提醒”。关闭后没有电脑请求的振动、亮屏或推送，仍可手动进入“待处理”。多个本地对话同时等待时合并提醒，完成只安静更新。
- 自动打开确认卡片需要系统授权；v0.5.1 路径为：更多 → 设置与提醒 → 自动弹出确认 → 打开系统授权 → 选择“腕上遥控”并允许显示在其他应用上层。未授权仍可点通知处理；应用不创建常驻悬浮窗。OPPO 系统充电覆盖页仍可能挡住应用。
- 新请求在已亮屏时也会尝试打开对应确认页；息屏时才申请短暂唤醒并立即释放，沿用系统亮屏时长。相同请求不因刷新、重连或重新开启提醒重复振动。
- 电脑或手表先处理均可，另一端的旧操作失效。仅提供原请求中可完整展示的一次性选项；登录、敏感输入和未知类型回电脑处理。
- 原生共享适配的是本机客户端接口，不承诺跨版本兼容；未知版本或连接中断时关闭写能力，草稿和送达凭据保留，不自动重放。

## 0.4 兼容模式（DESKTOP_SHARED=0）

- 终端绿界面：纯黑、细线框、系统字体和原生复用列表，无发光、模糊或装饰动画。
- 首页只有一个“发送”：始终沿用当前对话；执行中发送为补充当前回合。点顶部标题进入列表，列表顶部“新建对话”；空白草稿首次发送才创建原生会话。长按标题打开更多操作。
- 手表对话保留各自的上下文、草稿和结果；切换浏览不会切换正在执行的任务。一个任务执行时可看其他记录，但不能在另一段对话发送或新建执行任务，暂不提供队列。
- 电脑 Codex 记录明确标注“只读”，只浏览历史，不直接续聊。现用 v0.3 手表会话会迁移；更早且没有本地归属记录的对话保守显示为只读，不根据工作目录猜测来源。
- 对话列表每页 20 项；消息先请求最近 10 个原生历史项，过滤工具过程后显示文字（最多跳过三页纯工具项），手表最多保留 30 条展示记录。更早记录按需加载，单条全文按约 1000 字符分页；超长消息只提供前 20000 字符并明确标注。
- 待确认只振动一次，通知定位到需要处理的对话，简要说明和选项置顶，详情按需展开；没有回应就持续等待。完成后安静更新，主动停止不振动；需要介入的失败才提醒。
- 新提醒请求全屏通知并短暂唤醒，立即释放唤醒锁，亮屏时长交给系统。OPPO 的充电界面、锁屏和后台策略可能阻挡卡片；通知仍保留。
- 识别语音后检查文字再发送；电脑确认接收才清空匹配的草稿。未确认送达的原请求编号保留，手动重试使用同一编号，不自动补发。草稿隔离保存在本机，卸载会删除。
- 网络和 JSON 处理在后台，文字流留在电脑端，只更新阶段变化；无 WebView、无 UI 定时刷新或逐字重绘。瞬时断线安静重连，活动任务连续三次失败才提醒一次，不擅自重试任务。

## 远程连接

推荐两端加入同一个 Tailscale 网络，使用电脑的 Tailscale IP。不需要将端口映射到公网。部分 OPPO 系统提示 VPN 会禁用蓝牙共享网络，关闭 VPN 并重启后恢复；Wi-Fi/手机热点路径需要自行确认。

手表不能打开登录网页时，可在电脑上完成手表生成的设备授权流程。不要分享登录链接或认证口令。

## 边界

- 电脑必须开机、联网且服务运行。暂无开机自启配置。
- 共享模式沿用桌面对话的项目与权限；旧版独立助手默认工作目录为 workspace/。不自动批准额外权限。
- 旧版独立任务超时 20 分钟；共享回合由原桌面所有者管理，不额外套用该执行器时限。当前最终回复最多保留 20000 字符；单条历史全文缓存也有同样上限，超长历史项带 clipped 标记。v0.5.1 活动正文预览最多 1000 字符。旧版独立任务的完整结果和日志在 server/ai-results/；共享会话的原记录由 Codex 保存。
- 停止任务不能回滚已经完成的修改。
- 本地 HTTP 不加密；仅用于可信局域网或 Tailscale 加密隧道，禁止直接暴露公网。
- 语音采用点按录音，最长 30 秒；电脑本地识别，识别文字经用户检查后发送，不自动执行。
- 首次录音须允许麦克风权限；无后台常听。录音只在内存中处理，不保存。
- 常驻监听使用一条长轮询连接，不持续持有唤醒锁；仅新待处理事件使用最长 1 秒的屏幕唤醒请求并立即释放。系统省电、网络切换或 Tailscale 被暂停时提醒可能延迟，后台稳定性和实际耗电需持续真机验证。
- 支持一次性的命令/文件确认及问题选项；不支持的权限请求拒绝，不自动放开权限。
- 暂不提供多用户隔离或任务队列。

## 本地语音识别安装

在项目目录运行：

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r server/requirements-voice.txt
.venv\Scripts\python.exe server/setup_voice.py
```

Start-PC.cmd 会优先使用此隔离环境。base 多语言模型首次下载约 145 MB，之后在电脑本地识别；Codex 回答仍需联网。模型与 .venv 不上传仓库。

## 助手接口

- POST /assistant/send：prompt、request_id、thread_id、new（新会话为 true）。
- GET /assistant/conversations?cursor=：分页对话目录及只读标记。
- GET /assistant/conversations/messages?thread_id=&cursor=：分页文字历史及活动任务摘要。
- GET /assistant/conversations/message?thread_id=&item_id=&page=0：已加载历史消息的全文分页；电脑仅缓存最近 64 条全文，缓存失效时重新打开历史。
- GET /assistant/state?thread_id=&compact=1：指定会话的当前状态、预览和待确认项。
- GET /assistant/events?after=revision&thread_id=&compact=1：最长等待 20 秒的状态变化通知。
- POST /assistant/activate：thread_id，仅请求原桌面接入已有对话，不发送任务。
- GET /assistant/attention?cursor=：共享模式的跨会话待处理分页。
- GET /assistant/preferences、POST /assistant/preferences：读取偏好；提交 desktop_attention_enabled 布尔值更新电脑确认提醒。
- POST /assistant/answer：待确认 id、thread_id、turn_id，加 decision=accept/decline 或 answers 对象。
- POST /assistant/stop：thread_id、turn_id，停止指定活动回合。
- POST /assistant/steer：prompt、request_id、thread_id、turn_id；兼容模式向指定活动回合补充，成功返回 supplement_accepted=true，每回合最多 32 次。当前共享原生接口因缺少回合绑定而拒绝此操作；客户端须遵守 can_steer，不能用该接口绕过限制。重复编号不重复投递，未知送达先检查当前任务。
- POST /assistant/voice：16 kHz 单声道 PCM WAV，最大约 1.1 MB，返回识别文字。

POST 使用 Bearer Token；GET 使用原有口令机制。以上接口只用于受信任私人网络。

state/events 支持 `compact=1`：省略 `reply`，保留 `summary`（完成/失败/中断时最多 180 字）、`needs_attention` 和 `task`；不带参数时返回有界的最终 `reply`。v0.4 兼容模式为 `protocol_version=4`，共享模式为 `protocol_version=5`；客户端和电脑服务须一起更新。操作仍传明确的会话/回合目标，内部投递凭据不通过接口返回。

v0.5.1 在共享状态中兼容增加 `reply_preview`，旧客户端可忽略；无当前公开正文、连接/状态无效或只有已结束的进度说明时为 `null`。有正文时结构如下：

```json
{
  "thread_id": "conversation-id",
  "turn_id": "turn-id",
  "item_id": "message-id",
  "text": "当前公开正文，最多 1000 字符",
  "version": 1,
  "complete": false,
  "clipped": false
}
```

客户端同时校验 `thread_id`、`turn_id`、`item_id`，同一消息只接受更新版本。`version` 随正文变化单调递增，相同快照不重复增加；`clipped` 表示正文超过预览上限。`complete` 只在该原生回合完成、失败或中断后为真，不代表执行成功。公开进度说明可以作为未完成预览，空最终消息或只有进度说明的已结束回合不会冒充最终回答；私有 reasoning、未知消息阶段及原始重试错误不进入正文。消息替换/删除、回合切换、版本缺口会重新绑定或清空预览。

首段、完成和确认状态立即发布；生成中的后续正文最多每秒发布一次，即使没有下一条原生事件也会按时刷新。`can_send=false` 表示当前不能提交下一条共享任务，不能仅根据旧的 completed 状态判断；执行中补充另看 `can_steer`。状态监听、激活对话和恢复网络均不重放任务。新增的服务端耗时日志使用请求关联摘要和本机单调时钟，不记录正文、令牌或完整接口地址，不能将两台设备的时钟直接相减。

对话归属、每段快照和发送凭据存放于 server/assistant-state-conversations/，不进入版本控制；迁移电脑时应与原状态文件一同保留。
